# Kingsway API Baseline

Baseline date: 2026-05-13  
Purpose: API contract checkpoint before the next large owner-driven update.

Primary contract files:

- `backend/api/openapi.yaml`
- `backend/api/frontend-contract.md`

## Contract Rules

1. Do not silently change existing request/response field names.
2. Additive response fields are allowed when old fields remain stable.
3. Breaking changes require an explicit note in this baseline or a newer baseline file.
4. Every authenticated frontend call must send `Authorization: Bearer <token>`.
5. Critical writes should send `Idempotency-Key`.
6. List endpoints must keep `limit` and `offset` behavior stable unless versioned.
7. User-facing frontend code must map backend errors to safe UI messages.

- `POST /v1/auth/logout`
- `GET /v1/me`
- `GET /v1/session`

  - `DELETE /v1/branches/{branch_id}`
  - `GET /v1/rooms?branch_id=`

  - `PATCH /v1/rooms/{room_id}`

## Known Flexible Areas

These will likely change after the owner meeting and should be treated as design-open:

- student trial/active lifecycle,
- lesson start/end and attendance,
- online exam flow and speaking recordings,
- payment lifecycle details,
- teacher swap salary allocation details.

Before implementing those areas, create/update:

1. DB migration.
2. OpenAPI contract.
3. Frontend API type.
4. Idempotency behavior.
5. Audit/event behavior.
6. E2E/integration test plan.
